1.1 What Actually Happens When You "Compile"

In interpreted languages, your source code is the program. In C++, your source code is a recipe, and the compiler is a chef that turns it into a native executable — raw machine instructions your CPU runs directly, with no interpreter or virtual machine in between. That directness is where C++'s speed comes from, and it is why C++ powers game engines, browsers, databases, trading systems, and the SDKs you'll learn to build in this book.

The recipe passes through four stages:

  1. Preprocessing. Lines beginning with # (like #include) are textually processed. #include <iostream> literally pastes the I/O library's declarations into your file.
  2. Compilation. Each source file (.cpp) is translated, independently, into an object file (.o / .obj) of machine code with unresolved references ("I call a function named print_report; someone else defines it").
  3. Linking. The linker stitches all object files and libraries together, resolving those references, and produces the final executable (or library).
  4. Running. The OS loads the executable and jumps to main().
Note Keep this pipeline in mind all book long. Many confusing C++ errors make sense once you know which stage produced them: an undefined reference is a linker error (a definition is missing), while expected ';' is a compiler error (your syntax is off).

1.2 The Three Compilers That Matter

Professional C++ means writing code that builds on all three mainstream compilers:

The mainstream C++ compilers (all free)
CompilerHome platformCommandNotes
GCCLinux (everywhere, really)g++The GNU compiler; default on most Linux distributions.
ClangmacOS (via Apple), Linux, Windowsclang++Famous for clear error messages; powers Apple's Xcode tools.
MSVCWindowsclMicrosoft's compiler, installed with Visual Studio Build Tools.

They implement the same ISO standards but at slightly different paces, and a few flags differ (for example, GCC/Clang use -std=c++23, while MSVC has no /std:c++23 switch yet and you ask for the same thing with /std:c++latest). This book flags the differences whenever they bite. This book compiles everything at C++23, so prefer the newest compiler you can get: GCC 13+, Clang 17+ (on macOS that means Apple clang 16, which ships with Xcode 16), or MSVC from Visual Studio 2022 17.13+ handle everything in these pages. None of the three implements every C++23 feature yet, and they finish at different times — when you need to know whether your compiler has a specific feature, check the compiler support table linked again at the end of today.

1.3 Install Your Toolchain

Pick your operating system and follow along. You'll install three things: a compiler, CMake, and Git.

Linux — Ubuntu / Debian

sudo apt update
sudo apt install build-essential gdb cmake git
g++ --version      # expect GCC 13 or newer on Ubuntu 24.04+
cmake --version    # expect 3.25 or newer

build-essential is a meta-package that pulls in GCC, g++, make, and the C library headers in one go. If your distribution ships an older CMake than 3.25, install the current release from cmake.org/download or via sudo snap install cmake --classic.

Linux — Fedora / RHEL-family

sudo dnf install gcc-c++ gdb cmake git
g++ --version      # expect GCC 14 or newer on Fedora 40+
cmake --version    # expect 3.27 or newer

Fedora also offers a one-shot developer group: sudo dnf group install c-development installs the compiler toolchain plus common build tools. To try Clang alongside GCC on either distribution: sudo apt install clang (Ubuntu) or sudo dnf install clang (Fedora).

Note Everything after installation is identical across distributions: the commands in this book (g++, cmake, gdb) behave the same on Ubuntu and Fedora. Only the package-manager step (apt vs dnf) and package names differ, and this book shows both wherever they diverge. On Arch: sudo pacman -S base-devel gdb cmake git.

macOS

xcode-select --install          # installs Apple Clang + system headers
# Install Homebrew from https://brew.sh if you don't have it, then:
brew install cmake git
clang++ --version               # expect Apple clang 16 or newer (Xcode 16+)
cmake --version

Windows

  1. Download Build Tools for Visual Studio 2022 from visualstudio.microsoft.com/downloads (scroll to "Tools for Visual Studio").
  2. In the installer, check the "Desktop development with C++" workload. This installs MSVC, the Windows SDK, and CMake.
  3. Install Git from git-scm.com.
  4. To compile from a terminal, open the "Developer Command Prompt for VS 2022" (or "Developer PowerShell") from the Start menu — the plain terminal won't find cl.
cl            # from a Developer prompt; prints the MSVC version banner
cmake --version
Common Pitfall On Windows, running cl in a normal terminal gives "'cl' is not recognized". MSVC needs environment variables that only the Developer Command Prompt sets. VSCode's CMake integration handles this for you later, but for hand compilation, always use the Developer prompt.

1.4 Set Up Visual Studio Code

Install VSCode from code.visualstudio.com, then add two extensions (Extensions panel, Ctrl+Shift+X / Cmd+Shift+X):

  • C/C++ Extension Pack (Microsoft) — IntelliSense (code completion), go-to-definition, and debugging support.
  • CMake Tools (Microsoft) — configure, build, run, and debug CMake projects from inside the editor. (Included in the pack above; verify it's there.)

Three features you'll use constantly:

  • IntelliSense: type std:: and a completion list appears. Hover any name to see its type and documentation.
  • Command Palette (Ctrl+Shift+P / Cmd+Shift+P): every command in VSCode lives here. Type "CMake" to see what CMake Tools can do.
  • Integrated terminal (Ctrl+`): a real shell inside the editor.

1.5 Your First Program — By Hand First

Before automating anything, compile one program manually so the pipeline from §1.1 is real to you. Create a folder day01 and inside it this file:

hello.cpp 
// hello.cpp — first contact with modern C++ (built at C++23)
#include <iostream>   // stream I/O: std::cout
#include <string>     // std::string

int main() {
    std::string who = "professional C++";
    std::cout << "Hello, " << who << "!\n";
    return 0;   // 0 = success; the OS sees this exit code
}

In the repo: implementations/day01/01-hello/

Line by line:

  • #include <iostream> — pulls in declarations for the standard output stream std::cout. Angle brackets mean "a standard/system header."
  • int main() — the entry point. Every C++ program has exactly one.
  • std::string who = ... — a real string type that manages its own memory. std:: is the namespace of the standard library; you will write it thousands of times, and that's fine.
  • std::cout << ... — the << operator sends values to the output stream, chained left to right.
  • "\n" — a newline. (You may see std::endl elsewhere; it also flushes the stream, which is usually unnecessary and slower. Prefer "\n".)

Compile and run it:

# Linux / macOS (use clang++ on macOS, g++ on Linux — same flags; see the note below)
g++ -std=c++23 -Wall -Wextra -Werror -o hello hello.cpp
./hello

# Windows (Developer Command Prompt)
cl /std:c++latest /W4 /WX /EHsc hello.cpp
hello.exe

Expected output:

Hello, professional C++!

Those flags are not optional decoration — they are professional habit:

  • -std=c++23 / /std:c++latest — select the language standard. Compilers default to older standards; always be explicit.
  • -Wall -Wextra / /W4 — turn on warnings. A warning is the compiler telling you about a probable bug for free.
  • -Werror / /WX — turn every warning into an error, so the build stops instead of scrolling past it. This is the habit that separates code you can trust from code that merely runs: a warning you can ignore is a warning you will ignore. Every sample in this book is built this way, and Day 20 puts the same setting in CI.
  • /EHsc — enables standard C++ exception handling on MSVC (GCC/Clang enable it by default).
Note

Asking for C++23 is the one flag the three compilers still spell differently, and both odd spellings bite on the very first program.

  • Windows. There is no /std:c++23 — Microsoft will add it when its C++23 support is finished, and until then /std:c++latest is how you get C++23. (Visual Studio 2022 17.13 and later also take /std:c++23preview, which turns on C++23 and nothing experimental.) Watch out: an unknown /std: value is not an error. cl prints "warning D9002: ignoring unknown option" and then builds at its default, C++14 — so a typo here gives you a program that runs and a standard you didn't ask for.
  • macOS. Apple clang 15 and earlier only know the older spelling -std=c++2b and reject -std=c++23. Apple's version numbers don't track upstream LLVM's, so check with clang++ --version: from Apple clang 16 (Xcode 16) on, -std=c++23 works.

The CMake projects from §1.6 onward duck both problems: set(CMAKE_CXX_STANDARD 23) asks for the standard by name and lets CMake pass whichever flag your compiler understands.

Do Always compile with -Wall -Wextra -Werror (GCC/Clang) or /W4 /WX (MSVC), and always pin the standard with -std=//std:. Fix every warning — you no longer have the option of skipping one.
Common Pitfall -Werror will stop a build over something small — an unused variable you added while debugging, a comparison between a signed and an unsigned number. That is the point: each of those is a real defect waiting for a bad input. Fix the cause rather than deleting the flag. When you later build somebody else's code that was never warning-clean, leave -Werror off for their targets, not for yours.
Don't Don't put using namespace std; at file scope in headers or serious code. It dumps thousands of names into your scope and causes surprising collisions. Writing std:: is the professional norm.
Core Guideline SF.7: Don't write using namespace at global scope in a header file

In plain words: a header is pasted into every file that includes it, so a using namespace there force-feeds thousands of names to every user of your library — and they can't undo it. Imagine two toolboxes that each contain a hammer:

// my_sdk.h — BAD: now EVERY user of your SDK has all std names loose
using namespace std;
void print(const string& s);   // whose 'string'? works today, collides tomorrow

// my_sdk.h — GOOD: say which toolbox each tool comes from
void print(const std::string& s);

If a user also has their own string type (game engines and old codebases do), the bad header makes their code stop compiling — and it's your library's fault.

1.6 Enter CMake — Building Like a Professional

Hand-compiling works for one file. Real projects have hundreds of files, libraries, tests, and three platforms to support. CMake is the de-facto standard tool for describing what to build; it then generates the platform-native build system (Makefiles, Ninja files, or Visual Studio projects) that does the building. One CMakeLists.txt, every platform.

Recreate the hello project the CMake way. Folder layout:

day01-cmake/
├── CMakeLists.txt
└── src/
    └── main.cpp
src/main.cpp 
#include <iostream>

int main() {
    std::cout << "Built with CMake on every platform.\n";
}
CMakeLists.txt 
# Minimum CMake version — 3.25 is a safe modern floor.
cmake_minimum_required(VERSION 3.25)

# Project name, version, and language.
project(hello_cmake VERSION 0.1.0 LANGUAGES CXX)

# Require C++23, portably, with no compiler-specific extensions.
set(CMAKE_CXX_STANDARD 23)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)

# A target: one executable named `hello`, built from one source file.
add_executable(hello src/main.cpp)

# Warnings, as errors, per compiler. (Generator expressions — explained on Day 18.)
target_compile_options(hello PRIVATE
  $<$<CXX_COMPILER_ID:MSVC>:/W4;/WX>
  $<$<NOT:$<CXX_COMPILER_ID:MSVC>>:-Wall;-Wextra;-Werror>
)

In the repo: implementations/day01/02-hello-cmake/

The key mental model: modern CMake is about targets. add_executable creates a target; target_compile_options (and friends like target_link_libraries) attach properties to that target. We will build on this model all the way to Day 19's SDK.

Configure and build — the same commands on all three platforms, with one Windows caveat: run them in the Developer Command Prompt, because the CMake installed by the "Desktop development with C++" workload is only on the PATH there:

cd day01-cmake
cmake -S . -B build        # -S source dir, -B build dir: configure
cmake --build build        # compile + link
./build/hello              # Windows: .\build\Debug\hello.exe

Expected output:

Built with CMake on every platform.
Note The build/ directory holds everything generated. This is an out-of-source build: your sources stay pristine, and cleaning up means deleting one folder. Add build/ to your .gitignore from day one.
Common Pitfall Editing CMakeLists.txt and wondering why nothing changed? You usually don't need to reconfigure — cmake --build build re-runs CMake when the file changed. But if the build directory gets into a weird state (e.g., after switching compilers), the reliable fix is: delete build/ and configure again.

1.7 Open It in VSCode and Debug

Now connect the pieces. Open the folder: code day01-cmake (or File → Open Folder). CMake Tools will detect CMakeLists.txt and ask you to pick a kit — that's a compiler. Choose GCC/Clang/MSVC as appropriate. Then, in the status bar at the bottom:

  • Build button — runs the configure + build steps for you.
  • ▶ (Run) — builds and runs the target.
  • 🐞 (Debug) — builds and runs under the debugger.

To see the debugger earn its keep, replace src/main.cpp with a program that has actual state to inspect:

src/main.cpp 
#include <iostream>
#include <vector>

// Sum only the even numbers in a list.
int sum_of_evens(const std::vector<int>& values) {
    int total = 0;
    for (int v : values) {          // range-based for: visits each element
        if (v % 2 == 0) {
            total += v;             // ← set a breakpoint here
        }
    }
    return total;
}

int main() {
    std::vector<int> data{3, 8, 15, 4, 7, 10};
    std::cout << "Sum of evens: " << sum_of_evens(data) << "\n";
}

In the repo: implementations/day01/03-sum-of-evens/

Expected output: Sum of evens: 22.

Click in the gutter left of the total += v; line to set a red breakpoint dot, then press the 🐞 button. Execution stops at the breakpoint and you can:

  • Hover v and total to see their current values, or watch them in the Variables panel.
  • Step Over (F10) — execute one line.
  • Continue (F5) — run to the next breakpoint hit. Watch total go 8 → 12 → 22.
  • Inspect the Call Stack to see that you're inside sum_of_evens, called from main.
Do Reach for the debugger before sprinkling std::cout everywhere. Stepping through code with live variable inspection finds bugs faster and teaches you how your program actually behaves.

1.8 A Glimpse of "Modern" — Why This Book Exists

To close the day, here is one task solved twice: once the way C++98 was written, and once in the style this book teaches. The task: given a list of names, print each name with its length, longest name first. Don't worry about understanding every token yet — compare the shapes.

First, the C++98 way. This is not the caricature you may be expecting: the standard library already had std::vector, std::string, and std::sort, and this code uses all three. What it lacked was a way to say things briefly.

glimpse_old.cpp 
// C++98 style. Correct, and more capable than its reputation — but wordy.
#include <algorithm>
#include <iostream>
#include <string>
#include <vector>

// The sorting rule needs a name and a home, far from the call that uses it,
// because C++98 had no way to write a small function on the spot.
bool longer_first(const std::string& a, const std::string& b) {
    return a.size() > b.size();
}

int main() {
    std::vector<std::string> names;
    names.push_back("Ada");          // one call per element
    names.push_back("Grace");
    names.push_back("Bjarne");
    names.push_back("Margaret");

    std::sort(names.begin(), names.end(), longer_first);

    // Spell out the iterator type the compiler already knows.
    for (std::vector<std::string>::const_iterator it = names.begin();
         it != names.end(); ++it) {
        std::cout << *it << " (" << it->size() << ")\n";
    }
}

In the repo: implementations/day01/04-glimpse-old/

Nothing here is broken. The vector manages its own memory, the strings know their own lengths, and std::sort does the sorting — that is why C++98 was a real step forward. What it costs you is ceremony: the comparison rule sits in a function far from the one line that cares about it, the loop names a type the compiler could have worked out, and every name added is another push_back. Read the loop header again and notice how much of it is machinery rather than meaning.

Now the same task, modern style:

glimpse_modern.cpp 
#include <algorithm>
#include <iostream>
#include <string>
#include <vector>

int main() {
    std::vector<std::string> names{"Ada", "Grace", "Bjarne", "Margaret"};

    // Algorithm + lambda instead of a hand-written sorting loop.
    std::sort(names.begin(), names.end(),
              [](const std::string& a, const std::string& b) {
                  return a.size() > b.size();   // longest first
              });

    for (const auto& name : names) {            // range-for, no index bugs
        std::cout << name << " (" << name.size() << ")\n";
    }
}

In the repo: implementations/day01/05-glimpse-modern/

Both programs print exactly the same thing:

Margaret (8)
Bjarne (6)
Grace (5)
Ada (3)

Same library, same result, half the machinery. The sorting rule now sits inside the call that uses it, so you read what the sort does and why in one place. auto and the range-based for retire the iterator boilerplate, and brace initialization fills the vector in one line instead of four. Your code states intent — "sort by this rule" — where the older version spent its lines on mechanics. Add a fifth name and the rest of the program needs no edit. That gap between the two listings is the theme of the next twenty days.

Workshop

Q&A

Q: Should I learn C first?
A: No. Modern C++ is best learned on its own terms. C habits (raw arrays, malloc, char* strings) are precisely what modern C++ replaces.
Q: Which compiler should I standardize on?
A: Use your platform's native one day to day (GCC on Linux, Apple Clang on macOS, MSVC on Windows) and let CI build with all of them (Day 20). Code that compiles cleanly on all three is code you can trust.
Q: Why CMake instead of VSCode tasks or an IDE project?
A: CMake is toolchain- and editor-neutral: the same CMakeLists.txt drives VSCode, Visual Studio, CLion, plain terminals, and CI servers. Nearly every C++ library you'll depend on ships CMake support.
Q: Is return 0; required in main?
A: main is special: if control reaches its end without a return, the effect is return 0;. Many professionals omit it; either style is fine.

Quiz

  1. Which toolchain stage reports an undefined reference error?
  2. What do -Wall -Wextra do, and what does adding -Werror change?
  3. What is an out-of-source build and why is it good practice?
  4. In modern CMake, what is a "target"?
Quiz Answers
  1. The linker — it means a declaration was found at compile time but no definition was found at link time.
  2. They enable a broad set of compiler warnings — free, early bug reports. -Werror turns each one into an error, so the build fails instead of printing a warning nobody reads. Together they make "no warnings" a rule the compiler enforces rather than a habit you have to remember.
  3. All generated files go into a separate directory (e.g., build/), keeping sources clean; cleanup is deleting one folder, and multiple configurations can coexist.
  4. A named buildable thing — an executable or library — to which you attach sources, options, and dependencies with target_* commands.

Today's Project: daysleft — a Tiny Command-Line Tool

Build a small but honest tool: given a number of pages in a book and pages you read per day, it reports how many days you need to finish. It exercises everything from today: a CMake project, command-line arguments, basic validation, and exit codes.

daysleft/
├── CMakeLists.txt
└── src/
    └── main.cpp
CMakeLists.txt 
cmake_minimum_required(VERSION 3.25)
project(daysleft VERSION 0.1.0 LANGUAGES CXX)

set(CMAKE_CXX_STANDARD 23)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)

add_executable(daysleft src/main.cpp)
target_compile_options(daysleft PRIVATE
  $<$<CXX_COMPILER_ID:MSVC>:/W4;/WX>
  $<$<NOT:$<CXX_COMPILER_ID:MSVC>>:-Wall;-Wextra;-Werror>
)
src/main.cpp 
// daysleft — how many days to finish the book?
// Usage: daysleft <total_pages> <pages_per_day>
#include <iostream>
#include <exception>   // std::exception — the base type we catch below
#include <string>

int main(int argc, char* argv[]) {
    if (argc != 3) {
        std::cerr << "usage: daysleft <total_pages> <pages_per_day>\n";
        return 1;                       // nonzero = error, for scripts/CI
    }

    int total = 0;
    int per_day = 0;
    try {
        total   = std::stoi(argv[1]);   // string → int; throws on garbage
        per_day = std::stoi(argv[2]);
    } catch (const std::exception&) {
        std::cerr << "error: both arguments must be whole numbers\n";
        return 1;
    }

    if (total <= 0 || per_day <= 0) {
        std::cerr << "error: both numbers must be positive\n";
        return 1;
    }

    // Integer ceiling division: 300 pages at 40/day = 8 days, not 7.
    const int days = (total + per_day - 1) / per_day;

    std::cout << "At " << per_day << " pages/day, you will finish "
              << total << " pages in " << days
              << (days == 1 ? " day.\n" : " days.\n");
}

In the repo: implementations/day01/07-daysleft/

cmake -S . -B build && cmake --build build
./build/daysleft 300 40

Expected output:

At 40 pages/day, you will finish 300 pages in 8 days.

Try it with bad input (./build/daysleft 300 banana) and check the exit code. Notice the pieces you'll deepen soon: std::cerr for errors vs std::cout for results, a first sighting of try/catch (Day 6 in full), and ceiling division without floating point.

Stretch goals: print how many pages remain on the final day; add an optional third argument for pages already read; step through the ceiling-division line in the debugger with inputs 300/40 and 320/40 and watch days.
